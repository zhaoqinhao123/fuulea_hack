# fuulea_hack

《文言诗文·课下注释闯关》的单文件页面补丁集。每个功能一个独立脚本，由 `loader.js` 拉起一个浮动面板按需加载。

## 注入（最短）

贴进「注释填空」的输入框，随便答错提交：

```html
<img src=x onerror="with(document)body.appendChild(createElement('script')).src='https://fastly.jsdelivr.net/gh/zhaoqinhao123/fuulea_hack@3.16/loader.js'">
```

155 字符，输入框没有长度限制，直接粘贴即可。面板出现在右下角。**再注入一次就是隐形开关**：面板开着时注入 → 整块隐藏；再注入 → 显形。藏起来时页面里只剩你原本的内容，录屏、投屏都不留痕迹。

> 注入串必须带 `https:` 协议。v3.2.1 及更早的 README 示例是不带协议的 `//fastly...`，页面本身用 `file://` 打开时，浏览器会把 `//fastly.jsdelivr.net/...` 解析成 `file://fastly.jsdelivr.net/...`，于是报 `net::ERR_FILE_NOT_FOUND`，插件根本不加载。

之后每次只要 44 字符：

```html
<img src=x onerror="eval(localStorage.fhL)">
```

> 首次注入时 loader 会把自身源码存进 `localStorage.fhL`，并记下版本号 `fhV`；版本一变就自己重新抓一份。
>
> **不用手记版本号**：面板 → 工具 → 🔄 版本更新（v3.6 新增），点「查询最新版」会自动查 jsDelivr / GitHub 上的最新标签、验证 CDN 可用，并给出两种注入串（纯注入串 / 带「版本vX.Y」前缀）一键复制，还能顺手刷新本机缓存。原来的 🧪 环境自检里也保留着同样的能力。
>
> 为什么不用 GitLab `/-/raw/`：它返回 `text/plain` + `nosniff`，`<script>` 标签拒执行。jsDelivr 走 GitHub 并给正确的 JS MIME，所以当主源。
>
> `cdn.jsdelivr.net` 在国内常被重置，所以注入串默认用 `fastly.jsdelivr.net`；loader 自身与模块加载会按 `cdn` → `fastly` → `gcore` → raw.githubusercontent → GitLab API 依次重试。

## 注入后没反应 / 还是旧版？

按这几条自查（v3.13.1 起面板会自己报警）：

1. **页面已经开过面板**：再注入一次是「隐藏 / 显形」的开关（设计如此），不会把已加载的旧代码换成新代码。要升级必须**先刷新页面**（F5 / 下拉刷新）让面板消失，再贴注入串。
2. **版本号对不上**：注入串里的 `@3.16` 要和仓库最新 tag 一致（工具 → 🔄 版本更新 → 查询最新版，会自动生成正确串）。
3. **CDN 打不开**：`fastly.jsdelivr.net` 在部分网络会被重置。把串里的 `fastly` 换成 `cdn` 或 `gcore` 再试；三者都不通就换网络。
4. **44 字符短串没反应**：短串读的是 `localStorage.fhL`，只在**同一个浏览器、同一个站点、且这台机器此前成功注入过一次**时有效。换浏览器、清过缓存、换了域名（`file://` ↔ `https://`）之后都必须先贴一次长串。
5. **页面把 HTML 转义了**：面板不出现时按 F12 看 Console，有没有 `Refused to load the script` / `net::ERR_...`。

v3.13.1 起，若注入的是新版本而页面还跑着旧版本，面板会直接弹提示「注入的是 v3.13.1，页面还跑着 v3.13：刷新页面（F5）后再注入一次」，不会再静默地什么也不发生。

## v3.16

- **视频上传的真正根因**：v3.14 的 `dataUrl.split(',')[1]` 遇到 `video/webm;codecs=vp8,opus;base64,...` 时，会在 **codec 的逗号** 处切开，只把 `opus;base64` 当成内容上传；GitLab 解码后正好是 7 字节（`A2 9B AC 6D AB 1E EB`），所以聊天室里只剩一个 `m`。v3.15 已把解析改成从 `;base64,` 标记后取数据，但当时很多页面还在跑缓存的 v3.14，所以看起来“没修好”。v3.16 补上强制升级与上传前校验。
- **上传前四道校验**：空文件、媒体文件过小、WebM `1A 45 DF A3` / MP4 `ftyp` / 图片文件头、base64 长度必须与本地字节数匹配。任何一项失败都直接提示，不写聊天消息。
- **失败不再发空消息**：`uploadFiles` 以前把 `{err}` 混在成功列表里、回调的 `errs` 永远是 `null`，导致空文件会发出一条空文本消息；现在错误单独返回，上传失败只显示「上传失败：…」，不产生消息。
- **旧坏视频提示**：历史 7 字节视频的卡片会显示「上传损坏：仓库里只有 N B」，点开播放会明确说「文件已损坏，任何设备都放不了」，不再只报「本机解析不了」。这些旧文件的数据从未真正上传，GitLab 无法恢复；如果录制端本机相册还留有原片，可从相册重发。
- **强制升级**：在旧版面板还开着时注入 v3.16 loader，会先把 v3.16 缓存到本机并自动刷新；刷新后再贴一次注入串即可。只贴旧的 `@3.14` / `@3.15` 串仍然只会隐藏/显形，必须先换成下面的 `@3.16` 串。
- **视频格式**：仍然优先录 WebM（VP8/Opus），只有浏览器不支持 WebM 时才自动回退 MP4/H.264（iPad/Safari 属于这种情况）。不建议强行改成 MP4：Chrome 的 MediaRecorder 输出 fragmented MP4，配合分片录制容易出现 moov 不完整，本机和后台都解不了。7 字节的坏文件换成任何格式都播不了，先修上传而不是换格式。
- 版本号 `TAG` / AI 头栏 / 聊天室徽标 / 主面板标签统一升到 3.16。

## v3.13.1

- **修「注入 v3.13 后还是旧功能、像没注入」**：`loader.js` 里的版本标记 `TAG` 忘了跟着升到 3.13，于是 v3.13 的 loader 仍然把所有模块（`room.js` / `cam.js` / `media.js` / `ai.js` …）从 `@3.12` 拉——面板能出来，但新功能一个都没有；自缓存判断也因此恒真，旧 loader 永远不刷新。现在 `TAG = '3.13.1'`。
- **注入版本 ≠ 运行版本时明确提示**（以前是静默切换显示/隐藏，看着就像「注入失败」）。
- **回退源锁到版本 tag**：raw.githubusercontent 与 GitLab API 两条回退路径以前固定用 `main`（停在 v3.9），失败回退时会悄悄加载好几个版本前的代码；现在按 `v3.13.1` tag 取。
- **为什么不是直接改 v3.13**：jsDelivr 对带版本号的 URL 回 `Cache-Control: immutable, max-age=31536000`，`@3.13` 一旦被浏览器/边缘节点缓存就再也刷不新（这次实测 `@3.12` 的内容改了、CDN 仍在发旧的）。只能开新版本号。
- 版本号 `TAG` / AI 头栏 / 聊天室徽标 / 主面板标签统一升到 3.13.1。

- **修「聊天室录的视频能发、但自己/别人/后台都看不了」**：真正原因不是容器选错，而是**下载回来的 Blob 类型不对**——`gitReq` 用 `responseType='blob'` 取 GitLab 的 raw 文件时，`Blob.type` 直接继承服务端 `Content-Type`（二进制常被回成 `application/octet-stream`/`text/plain`），`<video>`/`<audio>` 拿到这种 MIME 直接拒绝播放。所以以前换回 WebM 也一样看不了。现在 `loadMedia` 下载后按「消息里记的 mime → 文件扩展名」重新 `new Blob([...], {type})` 再缓存/播放，老消息（没记 mime）靠扩展名推断。
- **录像容器改成 WebM(VP8/Opus) 优先、MP4 兜底**：Chrome 的 MediaRecorder 输出 fragmented MP4，再叠加 `start(500)` 分片拼 Blob，容易得到 moov 残缺的文件。现在 `mods/cam.js` 与 `mods/media.js` 统一优先 WebM；只有浏览器不支持 WebM（Safari）才用 MP4，且 **MP4 不分片**。
- **录像先自检再发送**：录完先本地 `loadedmetadata` 试解一次（6 秒超时），解不了就提示「这段录像编码异常（本机都解不了），已取消发送」并不上传，不再把坏文件发出去；扩展名按真实 `blob.type` 决定（以前一律写 `.mp4`，内容与扩展名不符，下载后播放器同样打不开）。
- **相机页录像补声音**：`mods/media.js` 以前 `getUserMedia({audio:false})`，录出来全是哑的；现在单独申请麦克风并与视频轨合成，拒绝麦克风则静音录制。比特率从 12 Mbps 降到 3 Mbps 并加 60 秒上限（12 Mbps 一分钟就超 25MB 上限）。
- **视频播放失败不再一片黑**：聊天室视频层解码失败时显示「这段视频本机解不了（文件名）：点上方 ⏬ 下载…」；`mods/media.js` 的查看器提示同步改写。
- **聊天室可以调透明度 / 黑白背景**：标题栏新增 🌓（深色 / 浅色 / 跟随系统，键 `fh:room:theme`）与 ◐（背景透明度 15%–100%，键 `fh:room:op`）。底色单独一层 `.rm-bg`，透明度只淡背景不淡文字；硬编码颜色全部改成 CSS 变量，浅色主题一套换掉。`#__rm` 加了 `data-fh-skip="1"`，loader 的通用窗口注入不再往里塞按钮。
- **聊天室窗口可以拖出画面外**：`clampRect` 不再把窗口四边顶死在视口内，改成只保证「标题栏还有 120px 宽 / 24px 高在屏内」，拖出去一半、留一条边都能拖回来；拖动、载入、缩放共用同一套钳制。
- **语音转文字新增免费离线引擎**：没有 API Key 也能用——`@huggingface/transformers`（jsdelivr 取代码）+ Whisper（`Xenova/whisper-base`，权重走 `hf-mirror.com`，首次约 80MB，之后浏览器缓存），全程本地跑、免 key。🎤 面板可选「自动 / 浏览器 / 离线」引擎（键 `fh:room:asr`）：自动模式先用浏览器识别，遇到 `network`（Chrome 走 Google 云，国内基本连不上）自动切离线。离线听写是「录一段 → 停止 → 整段转写 → 填进输入框」，可改完再发。
- **浏览器识别修连续说话**：以前 `continuous=false`，且 interim 结果用「减长度」拼接会重复/丢字。现在 `continuous=true` + `onend` 自动续接（静音 60 秒被 Chrome 掐断也能续上），文字用「已定稿 + 当前临时」重算，不再重复。
- **语音消息的转写兜底**：发语音消息时若浏览器识别没出字，自动用离线 Whisper 补一份 transcript 随消息上传；老语音消息点「转文字」若没有文字，会出现「离线转写」按钮，转完只写进本地缓存（消息文件不可变，不回头改仓库）。
- 版本号 `TAG` / AI 头栏 / 聊天室徽标 / 主面板标签统一升到 3.13。

## 配置同步（v3.3）

`config/<id>.json` 结构（公开仓库，加密后才提交）：

```js
{
  v: 1, at, tag, id,                            // 版本 / 时间 / 插件版本 / 配置 ID（u+10 位 base36）
  kdf: { salt, iter: 150000 },                  // PBKDF2-SHA256
  hint,                                         // 昵称（明文，方便认领）
  wrapPin,                                      // AES-GCM(DK, KDF('pin|'+id+'|'+PIN))     ← 日常解锁
  wrapTok,                                      // AES-GCM(DK, KDF('tok|'+id+'|'+TOKEN))   ← 忘记 PIN 用
  wrapAdm,                                      // AES-GCM(DK, KDF('adm|'+id+'|'+管理员密钥)) ← 管理员重置用
  box: { tok, keys }                            // AES-GCM(DK, {上传用 Token, 全部配置键值})
}
```

- `DK` 是每份配置随机的 256 位密钥；PIN / Token / 管理员密钥只用来包裹 `DK`，都不落盘。
- 配置 ID 与 PIN 无关：重置 PIN 不改文件名，旧 PIN 立即失效。
- `box.keys` 只收 `fh:*`（主题、透明度、网页站点、便签、解除限时标记、AI 地址/模型/思考深度等）；排除 API Key、会话、聊天记录、聊天室缓存、token 用量、指令历史、`fh:mod:*` 源码缓存、`fh:cfg:*` 自身（含本机 PIN `fh:cfg:pin` / `fh:cfg:pinAt`）。
- v3.5 起 PIN 由插件生成并保存在本机：上传时若有 Token 就直接用本地 PIN 重写配置，成功页展示一次可复制的 PIN；恢复时先试本机 PIN，失败才弹输入框（换设备 / 清缓存）。每次上传都会换新盐和新的 `wrapPin`，旧 PIN 立即失效。
- 恢复流程：`pullConfig` → 没有读权限 Token 时先弹 Token（校验 `read_api`）→ 有本机 PIN 直接 `cfgPull(pin)`，否则输入 PIN → 列出 `config/` → 逐个试解 `wrapPin` → 命中即解 `box` → 写回 localStorage（含 `fh:ai:gitToken`）并 `cfgPinSet(pin)`。
- v3.6 起仓库是私有的（`yq-group2/fuulea_ai_repository`）：上传需要 Developer 及以上的写权限，读取（恢复 / 启动探测）需要 `read_api`。只用于读配置的 Token 存在本机 `fh:cfg:rTok`，恢复成功后会被备份里的真 Token 覆盖并清掉。

## 存档结构

```js
{
  score, earned,                                  // 顶栏数字 / 灵宠等级依据
  pets: [{ sp, name, pts }],                      // sp ∈ fox|qilin|cat|dog，pts 是旧字段
  wrong: { "fill:123": { ...q, yourAns, correct } },
  fav:   { "note:456": { ...q } },
  fillDone: { "123": 1 },
  name, history: [{ ts, mode, total, correct, gain, items }]
}
```

`localStorage` 键：`wycg_v3`（学习数据）、`wycg_rank_v1`（排行榜）、`wycg_lock_v1`（家长密码）、`fh:lockfree`（本机解除限时标记）；插件自身配置 `fh:*`（主题、主面板透明度、`fh:sites`、`fh:note`、AI 地址/模型/思考深度/Token 等），其中 `fh:ai:key` 永不上传，`fh:cfg:id` / `fh:cfg:at` / `fh:cfg:admKey` 记录本机云端配置状态，`fh:cfg:pin` / `fh:cfg:pinAt` 是本机保存的恢复 PIN（不上传、不再反复询问）；`fh:ai:roomRect` 记聊天室位置大小，`fh:room:cache` 是聊天室消息缓存（最多 200 条），`fh:ai:usage:<sid>` 记每个会话的 token 累计；`fh:acct` 存账号（用户名 / PIN 哈希 / 账号的 Key、Token、网页配置），同样不上传。
